# Требования к учебному стенду, версия 1.0

## Калькулятор

- CALC-01: операции add, subtract, multiply, divide над двумя числами.
- CALC-02: отрицательные числа, ноль, дроби с точкой или запятой допустимы. Экспоненциальная запись допустима. Пробелы
  по краям чисел допустимы.
- CALC-03: каждый операнд — конечное число в пределах ±10¹². Пустая строка, текст, NaN, Infinity, boolean и число вне
  диапазона отклоняются HTTP 400 с понятной ошибкой.
- CALC-04: деление на ноль вызывает ZeroDivisionError в бизнес-логике, API возвращает 400, интерфейс показывает «Деление
  на ноль запрещено.».
- CALC-05: результат отображается с точностью до 12 значащих цифр; сравнение float в тестах выполняется с допуском.
  Неконечный результат отклоняется.
- CALC-06: «Очистить» сбрасывает оба поля, операцию на сложение, ошибку и результат на «—». Запоздавший ответ запроса не
  отменяет очистку.
- CALC-07: is_prime_number принимает только int, исключая bool; для n < 2 возвращает False, для нецелого типа вызывает
  TypeError.

## Список задач

- TODO-01: заголовок после удаления крайних пробелов имеет длину 1–120 символов. Пустой ввод и одни пробелы запрещены;
  одинаковые заголовки разрешены.
- TODO-02: добавленная задача активна; флажок переключает состояние, текст завершенной задачи зачеркивается.
- TODO-03: фильтры «Все», «Активные», «Выполненные» показывают соответствующий набор.
- TODO-04: удаление удаляет выбранную задачу, включая фильтрованный список.
- TODO-05: счетчик показывает число активных задач во всем списке, независимо от фильтра.
- TODO-06: обновление страницы сохраняет задачи и их состояния. Фильтр после перезагрузки — «Все».
- TODO-07: сброс удаляет все задачи текущего режима без подтверждения; другой режим не затрагивается.
- TODO-08: пользовательский текст выводится как текст, без исполнения HTML.
- Режим `?mode=buggy` намеренно нарушает TODO-01, TODO-04 и TODO-05. Ожидаемое поведение в тестовой документации все
  равно определяется требованиями выше.

## Авторизация

- AUTH-01: валидная пара `student` / `Test123!`, сравнение чувствительно к регистру, пробелы не удаляются.
- AUTH-02: верный ввод переводит на `/account`, показывает успех и Logout.
- AUTH-03: неверный/пустой ввод показывает «Неверный логин или пароль.», HTTP 401.
- AUTH-04: `/account` без сессии перенаправляет на `/login`; Logout очищает сессию.

## Контактная форма

- FORM-01: name, email, message обязательны; крайние пробелы удаляются сервером.
- FORM-02: имя 2–60 символов; сообщение 10–1000 символов включительно.
- FORM-03: email не длиннее 120 символов, без пробелов, с единственным @ и точкой после @. Это учебная проверка формата,
  не проверка существования адреса.
- FORM-04: невалидная отправка возвращает 422 и ошибки у каждого невалидного поля; введенные данные остаются в полях.
- FORM-05: валидная отправка показывает «Форма успешно отправлена.», HTTP 200; письма и сохранение данных отсутствуют.
- FORM-06: браузерная встроенная валидация отключена через novalidate для стабильного текста ошибок; сервер проверяет
  все поля.

## API и окружение

- HEALTH-01: GET `/api/health` → HTTP 200, JSON `{"status":"ok","service":"testing-lab","storage":"none"}`.
- Локальный сервер Waitress, 8 потоков, без debug/reloader. Внешние ресурсы для отображения страниц не нужны.
- Основной браузер проверок — Chrome. Мобильная ширина 390 px означает адаптивную проверку веб-страницы, а не выполнение
  мобильной ЛР 7.
- Размер тела запроса ограничен 16 КиБ; более крупные запросы отклоняются HTTP 413.

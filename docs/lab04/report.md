# Лабораторная работа 4. Page Object и валидация

Цель: отделить взаимодействие со страницей от проверок. Объект: собственная контактная форма `/contact`.

`BasePage` содержит открытие страницы, поиск с ожиданием, ввод и клик. `ContactPage` содержит visit, submit и получение
ошибки поля. Проверки результатов находятся в тестах, а не спрятаны внутри действий страницы.

Позитивный сценарий: Иван / ivan@example.com / «Проверка контактной формы» → «Форма успешно отправлена.». Негативные:
поочередно пустое имя, email, сообщение; дополнительно неправильный формат email. Каждый тест проверяет точный текст
ошибки и отсутствие сообщения успеха.

## Матрица принятия решений

И = валидное имя, E = валидный email, С = валидное сообщение. Правила валидности — FORM-01 … FORM-03. Все восемь
комбинаций проверяются серверными параметризованными тестами; UI проверяет ключевые сценарии.

| Правило | И   | E   | С   | Отправка | Ошибки           |
|---------|-----|-----|-----|----------|------------------|
| R1      | Да  | Да  | Да  | Успех    | Нет              |
| R2      | Да  | Да  | Нет | Отказ    | Сообщение        |
| R3      | Да  | Нет | Да  | Отказ    | Email            |
| R4      | Да  | Нет | Нет | Отказ    | Email, сообщение |
| R5      | Нет | Да  | Да  | Отказ    | Имя              |
| R6      | Нет | Да  | Нет | Отказ    | Имя, сообщение   |
| R7      | Нет | Нет | Да  | Отказ    | Имя, email       |
| R8      | Нет | Нет | Нет | Отказ    | Все поля         |

Это полный набор комбинаций трех логических условий, а не всех возможных строк. Для классов и границ дополнительно
проверить: имя длиной 1/2/60/61, сообщение 9/10/1000/1001, email без @, без точки, с пробелами и длиной 120/121. Границы
входят в серверные тесты. Пробелы по краям удаляются.

Результаты — STATUS и XML в artifacts. Ручной прогон матрицы не заявляется выполненным.

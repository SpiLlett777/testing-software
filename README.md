# Практикум по тестированию ПО

Локальное веб-приложение без базы данных для ЛР 1–4, 6 и 8. В репозитории также находятся материалы ЛР 5 (публичное API)
и конфигурация ЛР 9 (GitHub Actions). Мобильная ЛР 7 — отдельный будущий этап.

## Быстрый запуск на Windows

В терминале из корня проекта:

```powershell
# Если окружение еще не создано:
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe run.py
```

Открыть http://127.0.0.1:5000. Остановить сервер: Ctrl+C. Активация окружения не нужна. Можно запустить `start.ps1` из
PowerShell; если политика выполнения скриптов запрещает запуск, используйте команду Python выше.

| Страница           | Назначение                              |
|--------------------|-----------------------------------------|
| `/calculator`      | Арифметика, ошибки, очистка             |
| `/todo`            | Исправный список задач                  |
| `/todo?mode=buggy` | Три намеренных дефекта для ЛР 2         |
| `/login`           | Вход: `student` / `Test123!`            |
| `/contact`         | Контактная форма с серверной валидацией |
| `/api/health`      | GET endpoint для k6                     |

Данные Todo хранятся в localStorage этого браузера отдельно для двух режимов. Кнопка «Сбросить список» очищает текущий
режим. При смене порта/origin список будет другим. Авторизация учебная, пользователь заранее задан. Сессии перестают
действовать после перезапуска сервера, если не задан постоянный `SECRET_KEY`. Стенд слушает только `127.0.0.1`,
предназначен для локального практикума; намеренные дефекты не нужно публиковать как рабочий продукт.

## Проверки

```powershell
# Бизнес-логика и сервер; браузер не нужен
.venv\Scripts\python.exe -m pytest tests/unit --junitxml=artifacts/lab06/unit.xml

# Selenium: установленный Chrome; ChromeDriver скачивается автоматически
.venv\Scripts\python.exe -m pytest tests/ui --run-ui --junitxml=artifacts/ui/results.xml

# То же с видимым окном браузера
.venv\Scripts\python.exe -m pytest tests/ui --run-ui --headed

# Публичное API (нужен интернет)
.venv\Scripts\python.exe -m pytest tests/api --run-api --junitxml=artifacts/lab05/python-api.xml

# ЛР 3: сначала запустите run.py в другом терминале
.venv\Scripts\python.exe -m scripts.browser_smoke --headed
```

UI-тесты сами поднимают временный сервер на свободном порту и закрывают его; отдельный `run.py` им не требуется. На
каждый тест создается новый профиль Chrome. Используются явные ожидания, а не фиксированные задержки. Скриншоты
сохраняются в `artifacts/ui`. `CHROMEDRIVER` позволяет указать путь к уже установленному драйверу, если скачивание
недоступно.

Обычный `pytest` запускает локальные проверки и явно пропускает UI/API без соответствующих флагов. Три теста
`bug*_reproduced` подтверждают наличие намеренных дефектов; их успех не означает исправность дефектного Todo.

## Postman — ЛР 5

Импортировать `postman/lab05.collection.json` и `postman/lab05.environment.json`. Выбрать окружение, открыть коллекцию →
Run collection → Run. Сохранить результаты и скриншот Runner в `artifacts/lab05`. Коллекцию также можно проверить
Newman:

```powershell
npm.cmd ci
npm.cmd run postman
```

Newman проверяет ту же коллекцию, но не заменяет требуемый заданием запуск через интерфейс Postman. POST и PUT на
JSONPlaceholder имитируют запись: последующий GET не обязан возвращать изменения.

## Нагрузка — ЛР 8

Портативный k6 уже скачан в `tools/bin/k6.exe` на этой машине. На другой машине установить k6 из официального
дистрибутива. Запустить `run.py` в другом терминале. Из корня проекта:

```powershell
.\tools\bin\k6.exe run -e VUS=10 -e DURATION=30s -e SUMMARY_PATH=artifacts/lab08/10vu.json load/k6/health.js
.\tools\bin\k6.exe run -e VUS=50 -e DURATION=10s -e SUMMARY_PATH=artifacts/lab08/50vu.json load/k6/health.js
.venv\Scripts\python.exe -m scripts.summarize_load
```

Порог учебного теста: p95 < 500 мс, доля HTTP-ошибок < 1%, все проверки ответа успешны. Пауза 0.1 с на итерацию, один
GET на итерацию. Использовать только собственный стенд. Результаты двух коротких тестов не определяют предельную
производительность.

## Отчеты и CI

- `docs/requirements.md` — требования и ограничения.
- `docs/lab01` … `docs/lab09` — документы по работам; ЛР 7 пока не выполняется.
- `docs/STATUS.md` — фактически выполненные проверки и оставшиеся действия.
- `artifacts` — доказательства запусков, без вымышленных результатов.
- `.github/workflows/run-tests.yml` — unit + UI при push/PR, публичное API при ручном запуске.

Собрать Markdown-отчеты с полными листингами приложения и тестов:

```powershell
.venv\Scripts\python.exe -m scripts.build_reports
```

Результат: `reports/labNN.md`. Это основа отчетов без кафедрального титульного листа. Невыполненные ручные пункты явно
отмечены. Публикация репозитория и зеленый GitHub Actions run пока требуют отдельного выполнения в аккаунте GitHub;
инструкция находится в `docs/lab09/report.md`.

Python-зависимости верхнего уровня закреплены после локальной проверки; `requirements-lock.txt` фиксирует полное
установленное окружение. Для воспроизведения можно устанавливать его вместо `requirements-dev.txt`.
